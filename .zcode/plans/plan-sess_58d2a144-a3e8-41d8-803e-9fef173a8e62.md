# План: возврат офлайн-доступа к последнему тексту (с учётом причин откатов)

Цель: без сети приложение открывается и показывает последний успешно загруженный выпуск (с пометкой, что он сохранён), клики по уже переведённым/выученным словам работают; новая правка не повторяет ошибку откатанной версии — «вспышку вчерашнего текста» при онлайн-открытии.

## 1. Файлы, которые потребуется изменить

| Файл | Изменение |
|---|---|
| `frontend/src/lib/offline.js` | **Новый** (~25 строк): чистая функция `offlineState({ cached, shownData, targetDate })` → `{data, error, notice}` — решение «что показать при недоступности сети» |
| `frontend/src/useDaily.js` | В ветке `catch` (строки 45–52) заменить инлайн-логику на вызов `offlineState` с `cached: loadDaily()` — падение в кэш любой даты. **Инициализатор (строка 18) не трогаем** — защита от показа устаревшего текста без пометки |
| `frontend/public/sw.js` | `VERSION "v1"→"v2"`; добавить `if (r.ok)` перед `c.put` в navigate-хендлере; добавить `warmBundles()` на `activate` — закэшировать хэшированные бандлы, вытащив URL из закэшированного `/index.html` регэкспом `(/assets\/[\w.-]+\.(js|css|woff2?))` (~15 строк). Это закрывает дыру «офлайн работает только со второго визита» |
| `frontend/src/lib/offline.test.js` | **Новый**: тесты на `node --test` (как `reading.test.js`) |

Бэкенд не меняется: `/api/*` сознательно не кэшируется SW, офлайн-контент — обязанность приложения.

## 2. Проблемы текущей архитектуры, которые учитываем

- **Причина откатов**: откатанная правка убирала проверку даты в инициализаторе → при онлайн-открытии утром показывался вчерашний текст без пометки. Поэтому: быстрый путь «кэш той же даты» оставляем, а кэш другой даты показываем **только** в `catch` — с пометкой `notice` (шаблоны уже есть в `useDaily.js:49-51`).
- **Дыра первого визита SW**: регистрация по `window load` → бандлы первого визита мимо SW → офлайн-оболочка ломается до второго визита. Лечится `warmBundles()` на `activate`.
- **Жизненный цикл SW у существующих пользователей**: смена версии + `skipWaiting` + `clients.claim()` (уже есть) обновят SW при следующем открытии; старый кэш `shell-v1` удалится в `activate`.
- **Осиротевший `dist/sw.js` с v2** — до пересборки деплой «оживит» отменённое поведение; в процессе работы v2 станет легитимным, главное — собирать dist из актуального исходника.
- **Однослотовый кэш** `localStorage["reader.daily"]` — офлайн доступен только последний выпуск; навигация по `?date=` без сети к другим датам останется ошибкой (в рамках задачи «доступ к последнему тексту», расширение — отдельная задача).
- **Клик по непереведённому слову офлайн**: `POST /api/translate` упадёт; в `App.jsx:96-98` уже гасится — слово остаётся русским. Подготовленные переводы и выученные слова работают офлайн (они в localStorage/saved daily).

## 3. Реализация с минимальным вмешательством

1. **`lib/offline.js`** — извлечь чистую логику (паттерн кодовой базы: `learned.js`, `selection.js` — чистые модули под `node --test`):
   ```js
   export function offlineState({ cached, shownData, targetDate }) {
     const data = shownData ?? cached ?? null;
     if (!data) return { data: null, error: "Не удалось получить материал. Проверьте подключение и попробуйте снова.", notice: null };
     return { data, error: null,
       notice: data.date === targetDate
         ? "Нет связи с сервером — показан сохранённый выпуск."
         : `Не удалось обновить материал. Показан сохранённый выпуск за ${data.date}.` };
   }
   ```
2. **`useDaily.js`**: в `catch` — `setState(s => ({ ...s, loading: false, ...offlineState({ cached: loadDaily(), shownData: s.data, targetDate: date }) }))`. Инициализатор, фоновой перевод и `visibilitychange` — без изменений.
3. **`sw.js`**: bump версии; на `activate` после `clients.claim()` вызвать `warmBundles()` (читает `/index.html` из кэша, находит `/assets/…`, параллельно `fetch`+`put`, ошибки молча глушатся — сеть может быть недоступна); в navigate-хендлер добавить `if (r.ok)`. Структура хендлеров v1 сохраняется.
4. Пересобрать `frontend/dist`.

## 4. Тесты

`frontend/src/lib/offline.test.js` (`node --test`, запуск — `cd frontend && npm test`):
- офлайн + кэш той же даты → `data` из кэша, notice «Нет связи…», `error: null`;
- офлайн + кэш другой даты (утренний сценарий) → показан сохранённый выпуск, notice содержит его дату — **регрессия на баг откатанной версии с другой стороны**;
- офлайн + кэш уже на экране (`shownData`) → приоритет экcranного, без подмены;
- офлайн + кэша нет → `error`, `data: null` (экран «Повторить»);
- онлайн-инициализация: `cached?.date !== target` → `data: null` (защита от «вспышки вчерашнего текста» — фиксируем текущее поведение инициализатора тестом, чтобы его случайно не «оптимизировали» снова);
- идемпотентность/чистота функции (не мутирует вход).

SW автоматически не тестируется (нет инфраструктуры) — ручной чек-лист: `npm run build && npm run preview`, DevTools→Offline: (а) первый визит онлайн → офлайн: приложение загружается и показывает текст с пометкой; (б) переход через `?date=` на незакэшированную дату офлайн → экран ошибки с «Повторить»; (в) после нового деплоя старый кэш очищается.

## 5. Риски и пограничные случаи

- **Показ устаревшего контента без пометки** — главный риск; защищён сохранением дата-гарда в инициализаторе + тестом на него.
- **`?date=` офлайн на другую дату** — останется ошибкой (осознанное ограничение однослотового кэша, помечено в UI кнопкой «Повторить»).
- **Полночь при открытом приложении**: `visibilitychange` → `load()` → офлайн → сценарий «другая дата» → пометка с датой сохранённого выпуска (покрыт тестом).
- **`warmBundles()` при недоступной сети** — все ошибки глушатся, активация SW не падает; при следующем `activate` попытка повторится.
- **Приватный режим Safari/квота localStorage** — уже обёрнуто `safe()` в `storage.js`; поведение деградирует до онлайн-режима.
- **Часовой пояс клиента**: дату «сегодня» определяет клиент (`localDate()`) — между кэшем и запросом возможно расхождение на границе суток; сценарий уже покрыт notice «за такую-то дату».
- **Деплой**: убедиться, что CI/деплой собирает dist заново (сейчас в репо лежит несвежий артефакт с v2-SW).

Объём: ~70 строк нового кода + ~60 строк тестов, три существующих файла затрагиваются точечно.
